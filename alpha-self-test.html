Five-minute self-test.

Run this before you start real testing. It confirms your install works on your machine. Five short checks, about a minute each. If anything fails, the troubleshooting section tells you what's likely wrong.

Total time: ~5 minutes if everything passes. For broader reference material, see the tester guide.

Before you start

You need:

  • A working norm install. See the early-access page if you haven't installed yet.
  • One Word document (.docx) you don't mind ingesting. Any docx will do — a real document is better than a blank one. If you don't have one handy, save any Word doc to your Downloads folder.
  • A terminal window for running CLI commands (PowerShell on Windows, Terminal.app on macOS).
  • A browser for the web UI.

Run the five checks in order. If a check fails, stop and consult Troubleshooting at the bottom before continuing — later checks may fail for the same reason and aren't worth running until the first one is sorted.

01 CLI ingest

In a terminal:

  1. Run norm.
  2. At the > prompt, run /ingest <full path to your docx>. Examples:
WIN/ingest C:\Users\you\Downloads\test.docx MAC/ingest ~/Downloads/test.docx
A bordered WORD INDEXED card appears, listing paragraph count, table count, word count, and a structure tree. No red error text or Python traceback.

Mark PASS or FAIL. If FAIL, see Troubleshooting → CLI failures.

02 Web /ingest

Exit the CLI (Ctrl-C on Windows, Cmd-C or Ctrl-C on macOS). In a fresh terminal window, run:

norm --web

Open your browser to the URL it prints.

  1. In the chat input at the bottom of the page, type /ingest <full path to your docx> and press Enter.
A "Tavern" message bubble appears with an **Ingested:** summary, including file type, word count, and a preview of the content. The file should also appear in the right-rail Files panel.

Mark PASS or FAIL. If FAIL, see Troubleshooting → Web ingest failures.

03 Paperclip upload

In the same browser tab:

  1. Click the 📎 icon in the chat input row.
  2. In the file picker, select the same docx you just used.
A Tavern bubble appears matching the shape of Check 02. The file should not appear twice in the Files panel — it's the same file.

Mark PASS or FAIL. If FAIL, see Troubleshooting → Web ingest failures.

04 Drag-and-drop

  1. From your file manager (File Explorer on Windows, Finder on macOS), drag the same docx onto the chat window.
As you drag onto the window, a teal-bordered overlay fades in saying "Drop file to ingest." Releasing your mouse closes the overlay and produces another Tavern bubble.

Mark PASS or FAIL. If FAIL, see Troubleshooting → Web ingest failures.

05 Ask Rebecca

This confirms the agent layer works, not just ingestion.

  1. From the agent dropdown at the top of the chat, select Rebecca-Deck.
  2. Send: build me a board deck for Q1
A plan card appears (from Sam, the router). Then Rebecca's reply streams in. Her reply should ask for source data or reference your uploaded file, mention deck structure (executive summary, KPIs, etc.), and explicitly refuse to fabricate numbers if you haven't given her any.
Failure signal. If Rebecca produces a deck full of TBD placeholders without asking — or fabricates numbers without sourcing them — something is wrong with skill loading.

Mark PASS or FAIL. If FAIL, see Troubleshooting → Agent failures.

Troubleshooting

CLI failures

  • python-docx not installed (or any ModuleNotFoundError). Install issue, not a TavernOS bug. Reactivate your virtual environment and rerun pip install -r requirements.txt from the tavernos-alpha folder. If the error persists, email support.
  • Traceback ending in AttributeError: 'NoneType' object has no attribute .... Known regression class. Email the full traceback to support@tavernos.ai.
  • No such file or directory. Your path is wrong. Use the full absolute path. If it contains spaces, wrap it in quotes:
WIN/ingest "C:\Users\you\My Folder\file.docx" MAC/ingest "~/My Folder/file.docx"

Web ingest failures

  • HTTP 500 in the browser console. Server-side error. Switch to the terminal window where norm --web is running and copy the actual error text from there. Email it to support@tavernos.ai.
  • Drop overlay doesn't appear during drag. Browser-specific. Try a hard-refresh:
WINCtrl-Shift-R MACCmd-Shift-R

If still broken, note your browser name and version when emailing support.

  • /tmp path appears in any error message on Windows. Known historical bug, should be fixed in current builds. If you see it, you may be running an older build — email support with the version you're on.

Agent failures

  • Generic deck output with TBD placeholders and no questions. Skill loader isn't reaching Rebecca. Email support, mention "Rebecca skill_bodies" in the subject.
  • Crash, blank reply, or stream stops mid-response. Check the terminal window for a traceback and email it.
  • Wrong agent responds. Sam routed to the wrong skill. Note what you sent and what agent answered, email support.

Anything else

If the symptom doesn't match the above, email support@tavernos.ai with what you tried, what you expected, and what you saw. Don't worry about whether it's "really a bug" — surfacing the symptom is the alpha's job.

All five passed?

You're set. Continue with the rest of the alpha — see the tester guide for what to test next.

If you hit something during the five checks but everything eventually passed (e.g., a refresh fixed it), email support anyway. Intermittent bugs are the most valuable to surface early.
