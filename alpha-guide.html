What it is

TavernOS runs on your machine. You ingest documents — Word, PDF, Excel, PowerPoint, plain text, email exports — and specialist agents read them and produce work products: board decks, briefs, summaries, audits.

Ingested files live in a local SQLite database, scoped per client. Nothing leaves your computer except the questions you send to the AI.

What's in alpha

The alpha covers the core ingest-and-respond loop:

  • File ingestion via three paths: CLI /ingest, paperclip button in the web UI, drag-and-drop onto the chat window.
  • Per-client file isolation — keeping work for different clients in separate scopes.
  • A small roster of pre-built agents (Sam routes; Rebecca builds decks; others domain-specific).
  • The alpha demo workflow: ingest a real document, ask an agent to do something with it.

What's not in scope is in Limits at the bottom.

Setup

Windows is the primary alpha target. macOS is supported but less tested — if you're on Mac, expect to be the one finding the platform-specific bugs.

The full install walkthrough lives on the early-access page sent to you. The notes below are reference material for once you're already running.

Verify the install — open a terminal and run:

WINnorm MACnorm

You should reach a > prompt. Type /help to confirm commands are available, then exit with Ctrl-C (Windows) or Cmd-C / Ctrl-C (macOS).

Terminal app: on Windows use PowerShell. On macOS use Terminal.app (built in) or iTerm2 if you have it. Either is fine.

First launch (web UI) — in the same terminal:

norm --web

The terminal will print a URL — open it in your browser.

You should see the chat interface: an agent dropdown at the top, a message area in the middle, an input row at the bottom, and a right-rail panel labeled Files.

Quick start · first five minutes

Once installed, walk through this end-to-end. The longer version with pass/fail signals is on the self-test page.

  1. Launch norm --web. Open the browser to the URL it prints.
  2. Drag a Word document onto the chat window from your file manager (File Explorer on Windows, Finder on macOS). You should see a teal "Drop file to ingest" overlay, then a confirmation bubble after you drop.
  3. The file appears in the right-rail Files panel.
  4. From the agent dropdown, pick Rebecca-Deck.
  5. Send: build me a board deck for Q1 using the file I just uploaded.
  6. Rebecca should reference your file's actual content. If she asks for source data without acknowledging your upload, something is wrong — see self-test troubleshooting.

Bringing files in

Three ways to ingest a file. All three share the same backend, so they should behave identically — if one breaks, the others probably will too.

  1. CLI /ingest — in norm, run /ingest <path>. Useful for scripted ingestion or if you live in the terminal.
  2. Paperclip button — in the web UI, click the 📎 icon in the input row. File picker opens.
  3. Drag-and-drop — drag a file from your file manager onto the chat window. The teal overlay confirms the drop target.

Test all three at least once during your alpha session. They exercise different code paths in the browser even though they end at the same backend.

Path examples by OS:

WIN/ingest C:\Users\you\Downloads\report.docx MAC/ingest ~/Downloads/report.docx MAC/ingest /Users/you/Downloads/report.docx

Both forms work on macOS. Tilde (~) is convenient; absolute paths are explicit. Pick whichever you prefer. On Windows, use the absolute path with backslashes; quote it if it contains spaces.

Supported formats: .txt, .md, .pdf, .docx, .xlsx, .pptx, .msg, .eml. Anything else fails with a clean error message rather than crashing.

Per-client model

TavernOS scopes ingested files by client. The default client is _self — your own work. To create or switch clients:

/client new /client switch <slug> /client list

/client new runs a short setup wizard. /client switch <slug> moves between existing workspaces. Files ingested under one client are not visible from another. Switching back returns you to that client's files.

This matters for alpha testing: if you ingest a file under one client and don't see it later, check which client is active in the chat UI before reporting a bug.

When it breaks

Email everything to support@tavernos.ai.

A useful bug report has:

  • What you did — exact sequence of clicks/types. "I dragged a docx onto the window" is good; "the upload broke" is not.
  • What you expected — the documented behavior, if relevant.
  • What actually happened — copy the error text or describe the UI state.
  • Files involved — if you can share the file that triggered the bug, attach it. If not, describe its shape (size, format, source — was it exported from Word, Google Docs, somewhere else?).
  • Environment — OS and version (Windows 11 / macOS 14.x / etc.), browser name and version, anything unusual.

Browser dev tools output is gold. If something fails in the web UI, opening the Console and Network tabs and capturing what you see there is more useful than a screenshot of the chat.

Known limits

These are intentional gaps for the alpha — please don't report them as bugs:

  • Local desktop only. Windows is the primary target; macOS is supported but less tested. Linux works for development but isn't an official alpha target.
  • Single-user. No multi-user, no cloud, no remote access.
  • No SharePoint integration. File references are local paths. SharePoint forward-compat is in scope for a later release.
  • No automated test suite. Internal verification is a manual checklist. If you hit something the checklist doesn't cover, that's exactly the kind of finding the alpha is for.
  • Agent roster is fixed. Custom agents aren't user-creatable yet.
